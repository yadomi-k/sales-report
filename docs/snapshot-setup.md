# 過去との比較のための「写し（スナップショット）」の設定手順書

VISORAの「過去との比較」（1か月前の時点・1年前の時点）を使うために、Salesforceで**毎朝、商談分割の写しを1行ずつ保存**する仕組みを作ります。
Apex・商談オブジェクトの変更は不要です（カスタムオブジェクト1つと、フロー2つ）。

| 比較 | 写しが必要か | 使えるようになる時期 |
|---|---|---|
| 前年同期（確定値） | 不要 | すぐ |
| 1か月前の時点（先月比） | 必要 | 写しを取り始めて約1か月後 |
| 1年前の時点（昨対比） | 必要 | 写しを取り始めて約1年後 |
| （今後）1週間前との比較（商談所有者軸） | 必要 | 写しを取り始めて1週間後 |

> 写しは、取り始めた日より前にはさかのぼれません。**早く始めるほど、早く比較できます。**

---

## 1. 全体の流れ

```
毎朝 5:00  フロー「VISORA 写しを取る」
           今年・来年が売上日の「実績」の商談 → その商談分割を1行ずつ VISORAスナップショット に保存
毎朝 4:30  フロー「VISORA 古い写しを消す」
           36日より前の写しを削除（月末の写しは残す）
VISORA     比較する日（例：1か月前）以前で、一番新しい写しを読み、今の数字と並べる
```

## 2. 容量の目安

- 商談分割が年5,000〜6,000件 → 今年＋来年の対象は1日あたり **約6,000〜8,000行**
- 1行 約2KB（Salesforceのカスタムオブジェクトの容量計算）→ **1日あたり約15MB**
- 毎日の写しを36日分 ＋ 月末の写しをずっと残す → **約550MB ＋ 年に約180MB**

**設定 → ストレージの使用状況** で「データストレージ」の空きを確認してください。足りない場合は、手順 6 の「36日」を短くする（1週間前の比較だけなら10日）か、月末の写しを残す年数を決めて手動で削除します。

---

## 3. カスタムオブジェクトを作る

**設定 → オブジェクトマネージャ → 作成 → カスタムオブジェクト**

| 設定 | 値 |
|---|---|
| 表示ラベル | VISORAスナップショット |
| オブジェクト名（API参照名） | `VISORA_Snapshot__c` |
| レコード名 | 写し番号（データ型：**自動採番**、表示形式：`SNAP-{000000000}`、開始番号：1） |
| レポートを許可 | オン（件数の確認に使う） |
| 項目履歴管理・活動 | オフ |
| リリース状況 | リリース済み |

### 項目（項目とリレーション → 新規）

**API参照名は下の表のとおりにしてください**（VISORAはこの名前で読みます。`src/config.js` の `snapshot`）。

| 表示ラベル | API参照名 | データ型 | 備考 |
|---|---|---|---|
| 取得日 | `SnapshotDate__c` | 日付 | **必須** |
| 月末の写し | `IsMonthEnd__c` | 数式（チェックボックス） | 数式：`DAY(SnapshotDate__c + 1) = 1` |
| 商談ID | `OpportunityId__c` | テキスト(18) | |
| 商談名 | `OpportunityName__c` | テキスト(255) | |
| 取引先名 | `AccountName__c` | テキスト(255) | |
| 商談所有者ID | `OpportunityOwnerId__c` | テキスト(18) | 今後の「1週間前との比較（商談所有者軸）」で使う |
| 商談分割ID | `SplitId__c` | テキスト(18) | |
| 分割所有者ID | `SplitOwnerId__c` | テキスト(18) | |
| 案件ステージ | `StageName__c` | テキスト(40) | |
| 受注確度 | `Possibility__c` | テキスト(20) | 検索用受注確度（受注・高・中・低）の値 |
| 売上日 | `SalesDate__c` | 日付 | |
| 分割の金額 | `SplitAmount__c` | 通貨(16, 0) | |
| 分割の利益額 | `SplitProfit__c` | 通貨(16, 0) | |
| 分割の％ | `SplitPercentage__c` | パーセント(3, 2) | |
| コンペ区分 | `Competition__c` | テキスト(40) | |
| 商談の売上金額 | `SalesAmount__c` | 通貨(16, 0) | 今後の「1週間前との比較」で使う（**今のうちから保存しておく**） |
| 商談の最終利益額 | `FinalProfit__c` | 通貨(16, 0) | 同上 |

> ID は「参照関係」ではなく**テキスト**にします。商談側に関連リストなどが増えず、商談オブジェクトに影響しません。

### 共有設定
**設定 → 共有設定** で、VISORAスナップショットの「組織の共有設定」を **公開/参照のみ** にします
（中身は商談の数字なので、VISORAの利用者全員が同じ写しを見られるようにします）。

## 4. 使っている分割タイプのIDを調べる

フローで「売上金額」の商談分割だけを取るために、**商談分割タイプのID**（`149` から始まる18文字）を調べます。
無効な分割タイプの分割レコードが残っていても、写しに二重に入らないようにするためです。

1. 右上の **歯車マーク → 開発者コンソール** を開く
2. 下のタブから **Query Editor** を選ぶ
3. 次を貼り付けて **Execute**
   ```sql
   SELECT Id, MasterLabel FROM OpportunitySplitType WHERE IsActive = true
   ```
4. 「売上金額」の行の **Id**（例：`1490K000000XXXXQAA`）をコピーする

- 2件以上出た場合：「売上金額」の行のIdを使う
- 0件の場合：`WHERE IsActive = true` を消して実行し、「売上金額」の行のIdを使う

このIdは、手順 5-3 の「レコードを取得」の条件 `SplitTypeId` 次の文字列と一致する（値）にそのまま貼り付けます。

## 5. フロー「VISORA 写しを取る」

**設定 → フロー → 新規フロー → スケジュールトリガフロー**

### 5-1. 開始の設定
| 設定 | 値 |
|---|---|
| 開始日 | 明日 |
| 開始時刻 | 5:00 |
| 頻度 | 毎日 |
| オブジェクト | 商談 |
| 条件 | 「すべての条件に一致」<br>`RecordTypeId` 次の文字列と一致する `0126F000000oIzAQAU`（実績）<br>`StageName` 次の文字列と一致しない `目標` |

### 5-2. リソース（新規リソース）
| 種類 | API参照名 | 内容 |
|---|---|---|
| 数式（Boolean） | `fx_IsTargetYear`（今年・来年が売上日の商談だけを対象にする。今年分は1か月後の先月比と1年後の昨対比に、来年分は年明けの先月比に使う） | `AND(NOT(ISBLANK({!$Record.EstimatedSaleDate__c})), YEAR({!$Record.EstimatedSaleDate__c}) >= YEAR({!$Flow.CurrentDate}), YEAR({!$Record.EstimatedSaleDate__c}) <= YEAR({!$Flow.CurrentDate}) + 1)` |
| 変数（レコード） | `varSnap` | オブジェクト：VISORAスナップショット、1件 |
| 変数（レコード） | `colSnaps` | オブジェクト：VISORAスナップショット、**複数の値を許可（コレクション）** |

### 5-3. 要素
1. **決定**「今年・来年の商談か」：結果「対象」＝ `fx_IsTargetYear` が `True`。デフォルトの結果は何もしない（終了）
2. **レコードを取得**「商談分割を取得」（「対象」の後）
   - オブジェクト：商談分割（OpportunitySplit）
   - 条件：`OpportunityId` 次の文字列と一致する `{!$Record.Id}`、かつ `SplitTypeId` 次の文字列と一致する **手順4で調べた商談分割タイプのId**（`149`から始まる18文字）
   - 保存するレコード数：**すべてのレコード**、項目：自動的に保存
3. **ループ**「分割ごと」：コレクション＝手順2の商談分割
4. **割り当て**「写しを作る」（ループの中）

   | 変数 | 演算子 | 値 |
   |---|---|---|
   | `{!varSnap.SnapshotDate__c}` | 次の値と等しい | `{!$Flow.CurrentDate}` |
   | `{!varSnap.OpportunityId__c}` | 次の値と等しい | `{!$Record.Id}` |
   | `{!varSnap.OpportunityName__c}` | 次の値と等しい | `{!$Record.Name}` |
   | `{!varSnap.AccountName__c}` | 次の値と等しい | `{!$Record.Account.Name}` |
   | `{!varSnap.OpportunityOwnerId__c}` | 次の値と等しい | `{!$Record.OwnerId}` |
   | `{!varSnap.SplitId__c}` | 次の値と等しい | `{!分割ごと.Id}` |
   | `{!varSnap.SplitOwnerId__c}` | 次の値と等しい | `{!分割ごと.SplitOwnerId}` |
   | `{!varSnap.StageName__c}` | 次の値と等しい | `{!$Record.StageName}` |
   | `{!varSnap.Possibility__c}` | 次の値と等しい | `{!$Record.PossibilityForSearch__c}` |
   | `{!varSnap.SalesDate__c}` | 次の値と等しい | `{!$Record.EstimatedSaleDate__c}` |
   | `{!varSnap.SplitAmount__c}` | 次の値と等しい | `{!分割ごと.SplitAmount}` |
   | `{!varSnap.SplitProfit__c}` | 次の値と等しい | `{!分割ごと.SplitProfit__c}` |
   | `{!varSnap.SplitPercentage__c}` | 次の値と等しい | `{!分割ごと.SplitPercentage}` |
   | `{!varSnap.Competition__c}` | 次の値と等しい | `{!$Record.Competition_classification__c}` |
   | `{!varSnap.SalesAmount__c}` | 次の値と等しい | `{!$Record.OrderEstimate__c}`（売上金額） |
   | `{!varSnap.FinalProfit__c}` | 次の値と等しい | `{!$Record.（最終利益額の項目）}` ※API参照名を確認 |
   | `{!colSnaps}` | **追加** | `{!varSnap}` |

5. **レコードを作成**「写しを保存」（ループの**後**）：作成するレコード数＝複数、レコードコレクション＝`{!colSnaps}`

### 5-4. 保存・テスト・有効化
1. フロー名：`VISORA 写しを取る`（API参照名 `VISORA_Take_Snapshot`）で保存
2. **デバッグ**で、売上日が今年の商談を1件選んで実行し、VISORAスナップショットに分割の数だけ行ができることを確認（確認後、テストでできた行は削除してよい）
3. **有効化**

> スケジュールトリガフローは、対象の商談ごとに動き、Salesforceが200件ずつまとめて処理します。商談分割の取得と写しの保存もまとめて行われるため、数千件でも制限にはかかりません。

## 6. フロー「VISORA 古い写しを消す」

**設定 → フロー → 新規フロー → スケジュールトリガフロー**

| 設定 | 値 |
|---|---|
| 開始時刻 | 4:30、毎日 |
| オブジェクト | （指定しない） |

1. **リソース** 数式（日付）`fx_DeleteBefore`：`{!$Flow.CurrentDate} - 36`
2. **レコードを取得**「古い写し」：オブジェクト VISORAスナップショット、条件 `SnapshotDate__c` 次の値以下 `{!fx_DeleteBefore}`、かつ `IsMonthEnd__c` 次の値と等しい `False`、すべてのレコード
3. **決定**「あるか」：手順2の結果が null でない
4. **レコードを削除**「削除」：手順2のレコードコレクション
5. 名前 `VISORA 古い写しを消す` で保存し、有効化

> 「36日」は「1か月前の時点」と比べるために必要な日数です。容量が足りない場合は小さくできますが、32日未満にすると「1か月前」の比較が月によって使えなくなります。

---

## 7. 権限

VISORAを使う人が写しを読めるようにします。

1. **設定 → 権限セット**（VISORA用の権限セット、なければ新規作成）
2. オブジェクト設定 → VISORAスナップショット → **参照**、すべての項目に**参照アクセス権**
3. VISORAを使う人に割り当てる

> フローはシステム（自動プロセス）として動くため、フロー側の権限設定は不要です。

---

## 8. 動いているかの確認

- 翌朝、**レポート**（VISORAスナップショット、取得日でグループ化、件数）で、その日の行数が商談分割の件数とおおよそ合うか確認
- VISORA の Sales タブ →「過去との比較」→「1か月前の時点」を選んで検索
  - 写しが1か月分たまるまでは「○月○日以前の写しがまだありません」と表示されます（正常です）
  - オブジェクトや権限がない場合は「写しの仕組みがまだSalesforceにありません」と表示されます

## 9. 注意点

- **受注の判定**：検索用受注確度の数式は、カスタム表示ラベル `StageNamesAsOrders` に含まれるステージを「受注」にしています。VISORAの `src/config.js` の `opportunity.wonStages`（受注・制作進行・請求・完了）と、この表示ラベルの内容をそろえてください。
- **目標**：比較のときの目標は、写しではなく今の【個人目標】を使います（1年前の時点の比較では、前年の【個人目標】）。
- **写しの内容を手で直さない**：写しは「その日の時点の記録」なので、後から修正しないでください。
